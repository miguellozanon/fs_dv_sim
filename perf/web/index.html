      Start here

      The Performance Lab predicts how fast the LR26 is in the four dynamic events of a Formula Student competition (acceleration, skidpad, autocross, endurance) and how many points that gives. Change something on the car, and it tells you within a second what it gains or costs. You do not need to code.

      1. Overview shows the car as it is: times, points and speed on the track.
      2. Setup: type a new value (for example mass 270 instead of 284), press Apply and run. The bar at the top now shows the new total and the difference (green = better).
      3. Save setup keeps it for the team. Back to baseline returns to the real car.

      The bar at the top always says which car you look at. Every other page (Studies, Transient, Energy, ggV, Logs) works on that car. Nothing you do here changes the car's data files.

      How do I ...

      ... see how good a change is (e.g. 10 kg lighter)?
      1. Setup → Vehicle → Vehicle mass: type the new value, 274. (Relative changes also work: *0.96 = −4 %, +-10 = 10 less.)
      2. Press Apply and run. The top bar shows the new total and the change.
      3. Overview: which events gained, by how much time.
      ... find out which parameters matter most?
      1. Studies → Sensitivity → Run (about 6 s).
      2. The longest bars matter most. "P/%" in the table = points per 1 % change in the better direction.
      3. For mass you also get points per kg: useful to decide if a part that saves weight is worth its cost.
      ... find the best value of one parameter (e.g. gear ratio)?
      1. Studies → Sweep: parameter i_trans, from 12 to 23, 12 steps → Run.
      2. The top of the "Total points" curve is the best value; the dotted line is today's car.
      3. Check the per-event chart: a value can win one event and lose another.
      ... trade two things against each other (downforce vs drag)?
      1. Studies → 2-D map: c_z and c_w with their ranges → Run.
      2. Darker = more points. Hover over a square for its numbers. The best point is outlined.
      ... compare design options (old car, new wing, ...)?
      1. Save each option as a setup (Setup → Save setup).
      2. Studies → Compare setups: tick them → Compare. The table shows points per event; the right chart shows where on the lap each option gains or loses time.
      ... check if a driver (or the driverless car) can really reach these times?
      1. Transient → choose an event → Run.
      2. It drives the lap with a dynamic car model and a driver. Expect 3-8 % slower than the main result; the chart "time lost" shows where.
      ... plan the endurance energy (battery size, power limit)?
      1. Energy: type the usable battery energy in kWh (e.g. 5) → Run.
      2. It finds the highest power limit that still finishes 16 laps with that energy, and its points.
      3. "Where the energy goes" shows what to work on (brakes, drag, drivetrain).
      ... compare with a test drive?
      1. Logs → Upload the log (.mf4 from the car, or a .csv). Pick the speed channel and its unit.
      2. Choose the event and press Correlate. Small "speed RMSE" (a few km/h) = the model fits the car.
      3. The offset is found automatically; type a number only if the start of the log and the timing line differ a lot.
      ... use the motor efficiency measured on the car?
      1. Logs → choose an .mf4 with the inverter channels → Analyse → give it a name → Save map.
      2. At the top, Motor efficiency: choose the map. All energy numbers now use it.
      ... share my work with the team?
      1. Saved setups are files in lapsim\configs: they are shared with the driverless simulator and go to git with the project.
      2. Every table and chart has Export CSV (for Excel).
      3. The launcher window: Back up setups makes one zip of all setups.
      ... change the car for good (new baseline)?

      The baseline is lapsim\LR26_LapSim\config\lr26_params.m, the Performance department's file (MATLAB). Change it only when the department agrees: every tool of the team uses it. The Lab reads it again by itself; reload the page.

      The pages

      Overview
      All four events: time, points, change against the baseline, speed and accelerations along the lap, speed on the track map, battery power. Click an event name above the charts to switch.
      Setup
      Every car parameter with its unit and baseline value (grey). Type a value to change it; *1.05 = +5 %, +10 = add 10. "Other changes" takes anything else in LapSim notation, e.g. autocross.util_y=0.85 (driver uses 85 % of the grip in autocross).
      Studies
      Sensitivity: every parameter ±10 %. Sweep: one parameter over a range. 2-D map: two parameters. Compare setups: saved setups side by side. Long studies show a progress bar and can be cancelled.
      Transient
      A check of the main (quasi-steady) result with a car that has yaw, steering and a driver. Shows time lost along the lap, steering, side slip, how far the car is from the line.
      Methods
      The same car with different lap time methods, to choose the one that fits the question. QSS (the main result) is fast and good for rankings. Optimal control finds the fastest way round for a perfect driver: the point mass checks QSS, the single and double track add steering, yaw, load transfer and torque vectoring. Compare the methods: does every method agree that a change helps? Robustness: is a gain bigger than what we do not know about the car (grip, mass, aero)? The table on the page says which method to use for which question; PERF_METHODS.md explains each method, its hypotheses and limits. The optimal-control models need the package CasADi (the launcher's Repair installs it).
      Energy
      Energy of the endurance, where it goes, endurance points against the power limit, and the power limit for a battery energy you type in. Recuperation: how much energy each regen power saves, and with a battery budget how many endurance points that buys.
      ggV
      How hard the car can accelerate, brake and corner at each speed (in g). Engineers use it to compare cars and as input for other tools.
      Logs
      Car logs (.mf4) or CSV files against the simulation, and the motor efficiency from inverter logs. Identify the car from the log turns test-day runs into model numbers: a coast-down gives drag and rolling resistance, any fast running gives how much of the grip the driver used, a steady circle gives the grip, and a GPS lap gives a track file. What to log and how to run the test day: LOGGING_SPEC.md.

      What the numbers mean (and what they do not)

      • Points are the competition's formula for each dynamic event (more points for a shorter time, up to 50 / 50 / 100 / 250 for acceleration / skidpad / autocross / endurance). The total is the four dynamic events only: no efficiency, no static events (design, cost, presentation).
      • The main result is a quasi-steady-state (QSS) simulation: at every point of the track the car is exactly at its limit. It is a little optimistic; real cars are 3-8 % slower (see Transient). Use it to compare changes, not to promise lap times.
      • The tracks are the FSA 2025 tracks (choose "real" at the top for the measured versions). Different tracks give different absolute times; the ranking of changes usually stays the same.
      • Driver utilisation (util) is how much of the tyre grip the driver uses in each event (1 = all of it).
      • The model is as good as its numbers. Tyre grip and mass matter most, so their values should come from tests.

      Glossary and all parameters

      QSS
      Quasi-steady-state: the lap is computed as a chain of steady states (no yaw, no driver delays). Fast and standard for studies.
      Transient
      A simulation in time with the car's dynamics and a driver, closer to a real lap.
      Flying lap
      A lap that starts at racing speed (skidpad, endurance), unlike a standing start (acceleration, autocross).
      Corner speed
      The highest speed at which the car can take a curve without sliding.
      Friction ellipse
      A tyre has one budget of grip for braking/accelerating and cornering together; using it for one leaves less for the other.
      Load transfer
      Weight moves to the front when braking, rearwards when accelerating, outwards in corners; it changes the grip of each tyre.
      Downforce / drag
      Aero force pushing the car down (more grip) and holding it back (less speed). c_z and c_w are their coefficients.
      Sensitivity (P/%)
      Points gained by changing a parameter by 1 % in its better direction.
      Power cap
      The motor power limit used in the endurance to save energy.
      EF (efficiency factor)
      Endurance time² × energy; the efficiency score of the rules is built from it (smaller is better).
      ggV
      Acceleration limits (in g) for each speed: drive, brake and corner.
      RMSE
      Average size of the difference between log and simulation (root mean square error).
      Setup
      A list of changes on top of the baseline car, saved under a name.

      Something does not work

      The page does not open / "This site can't be reached"
      The Lab is not running: open the Performance Lab window (desktop shortcut or Performance Lab.bat) and press Start and open.
      "unknown parameter ..."
      A name in "Other changes" is misspelt. The names are in the parameter table above (column "Name"), e.g. m, c_z, i_trans.
      A change does nothing
      Some parameters have no effect in some events (e.g. more power when the car is limited by motor torque). Sensitivity shows "no effect" for those. Check the change is listed in the top bar.
      A study takes long
      2-D maps run every combination (8 × 8 = 64 runs ≈ 20 s). Use fewer steps, or Cancel.
      The numbers differ from MATLAB
      They should agree exactly for the same changes and competition file. Check both use the same competition (top bar) and efficiency (constant or a map).
      Anything else
      In the launcher window, Save a help report and send the zip to the team's software contact. It holds the checks and logs, no car data.
