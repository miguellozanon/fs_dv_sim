        Share with Claude

        One report with the system state, the simulation steps, every process and job, their logs and result tables.

        RL & Performance tools

        Each tool runs in the background; follow it under Jobs. Vehicle changes use the LapSim names.

        Performance Lab

        The lap time simulation on its own: points per event, sensitivities, sweeps, setup comparison, transient lap, energy, ggV and car logs. Runs on Windows in its own window (no WSL needed): also Performance Lab.bat in the project folder or the desktop shortcut it can make.

        Its page (when running)

        Official runs: RL vs reference

        Complete missions in the full simulator (timing, cones) for any setup.

        Setup sweep (universal RL)

        Many setups × tracks at once in the batched model: times, limits, sensitivities, LapSim next to them.

        Parameter study

        LapSim, the DV target and the closed-loop simulation for each value; HTML report.

        Train the universal policy

        One policy for every setup in the ranges (PPO). GPU: about 1500 iterations; CPU: hours.

        Train the cone detector (YOLO)

        Ultralytics YOLO11 on the camera images recorded in Isaac Sim, on the GPU.

        Train for one setup

        Evolution strategies on the CPU for exactly one vehicle setup (10–40 min for 50 generations).

        Maintenance

        Update

        Installs Downloads\fsg-dv-sim.zip over this copy and builds it (what unzip + fsgbuild do). Stop the simulation first.

        GPU (PyTorch)

        GPU training and GPU sweeps use the Windows Python when it has PyTorch with CUDA, else PyTorch in WSL.

        Camera cones (YOLO)

        Training runs on the Windows Python (Ultralytics, AGPL-3.0); the car's detector runs in WSL with ONNX Runtime (OpenCV's DNN module if it is missing).

        GitHub / GitLab

        Commits this copy and pushes it to both repositories at once (Git for Windows; the first push opens a browser sign-in for each site, then it is remembered). Code and trained models only: the CAD, the LR26 body USD and the LapSim stay out, and a push that would include them is refused.
